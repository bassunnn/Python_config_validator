# Документация тест-кейсов для проверки конфигурационного JSON-файла

Данный документ содержит набор тестовых сценариев для проверки корректности конфигурационного файла в соответствии с требованиями тестового задания Kaspersky.

---

## 1. Спецификация требований и бизнес-правил

| Параметр / Объект | Тип данных | Обязательность | Допустимые значения и ограничения |
| :--- | :--- | :--- | :--- |
| **Файл** | Файловая система | Обязателен | Файл должен существовать, быть доступным для чтения, содержать корректный JSON, корневой элемент — JSON-объект (`dict`). |
| **host** | String | Обязательное | Непустая строка (не допускается пустая строка `""` или строка только из пробелов). |
| **port** | Integer | Обязательное | Целое число в диапазоне `[1, 65535]` включительно. Булевы типы не допускаются. |
| **timeout** | Number (int / float) | Обязательное | Число в диапазоне `[1, 300]` включительно. Булевы типы, NaN и Inf не допускаются. |
| **enabled** | Boolean | Обязательное | Строго булево значение (`true` / `false`). Числовые эквиваленты 1/0 запрещены. |
| **Набор полей** | Object keys | Обязателен | Все 4 поля (`host`, `port`, `timeout`, `enabled`) должны присутствовать. |

---

## 2. Техники тест-дизайна

В ходе проектирования тестов применены две ключевые техники тест-дизайна:
1. **Разбиение на классы эквивалентности (Equivalence Partitioning)** — разделение входных данных на группы допустимых и недопустимых значений, для которых программа ведет себя одинаково.
2. **Анализ граничных значений (Boundary Value Analysis)** — проверка поведения программы на границах допустимых диапазонов (значения на границе, непосредственно перед и сразу за границей).

| **BVA-PORT-03** | `2` | Допустимый | Значение `min + 1` (внутри диапазона) | Успешно -> `True` |
