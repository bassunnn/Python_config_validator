# Валидатор конфигурационных файлов

  

Проект представляет собой модуль для валидации конфигурационных JSON-файлов и полный набор независимых автоматизированных тестов на базе **pytest**.

Решение полностью кроссплатформенное и работает на **Linux**, **Windows**, **macOS** и протестировано со **100% покрытием строк и ветвлений**.

---

## Быстрый старт (Linux / macOS / Windows)

### 1. Требования

- Python **3.8+**

- Утилита `venv` или `virtualenv`

---

  

### 2. Подготовка виртуального окружения

  

#### На Linux / macOS:

```bash

# 1. Клонируйте репозиторий или распакуйте архив, затем перейдите в каталог проекта:
```

## Запуск автоматических тестов

  

Все тесты являются независимыми и используют фикстуру `tmp_path`, создающую изолированное дисковое пространство для каждого запуска.

### Базовый запуск тестов:

```bash

pytest

```

### Подробный запуск с выводом параметров (`-v`):

```bash

pytest -v

```

### Запуск с измерением тестового покрытия (Coverage):

```bash

pytest --cov=config_validator --cov-report=term-missing

```

**Результат**: 100% покрытие кода тестами (105 тестов, 0 пропусков).

  

### Запуск с выводом логов диагностики (`INFO` / `DEBUG`):

```bash

pytest -v --log-cli-level=INFO

```

  

### Запуск конкретной группы тестов:

```bash

# Только позитивные сценарии

pytest tests/test_validator.py::TestPositiveScenarios -v

  
# Только граничные значения порта

pytest tests/test_validator.py::TestPortFieldValidation -v

  
# Только негативные тесты на работу с файлами

pytest tests/test_validator.py::TestFileAndSyntaxScenarios -v

```

## Архитектурные решения и обоснование выбора

  
### 1. Стандартная библиотека Python vs Pydantic / jsonschema

В качестве основного решения выбрана **чистая стандартная библиотека Python** (`json`, `pathlib`, `logging`, `math`):

1.**Нулевые внешние зависимости в рантайме**: библиотека не требует установки сторонних пакетов для работы валидатора (зависимости нужны только для тестов и линтера).
2.**Минимальный оверхед**: парсинг и валидация происходят максимально быстро без тяжеловесного анализа метаклассов.
3.**Полный контроль над граничными условиями**: библиотеки вроде `pydantic` или `marshmallow` часто по умолчанию выполняют автоматическое приведение типов, например, преобразуя строку `"8080"` или булево `True` в число `1`, что может маскировать ошибки конфигурации. Ручная проверка типов гарантирует строгое соблюдение контракта.

---

### 2. Двухуровневая архитектура валидации и кастомные исключения

Реализовано разделение на два слоя:

1. **Низкоуровневый движок** (`load_and_validate_config`, `validate_config_dict`):
   - Выполняет детальный разбор.
   - В случае ошибки выбрасывает строго типизированное исключение из собственной иерархии:
     - `ConfigError` (базовый)
     - `ConfigFileNotFoundError` (файл отсутствует)
     - `ConfigFileReadError` (права доступа, директория вместо файла, ошибка кодировки, DoS-лимит)
     - `ConfigJSONDecodeError` (битый JSON, пустой файл)
     - `ConfigValidationError` (неверный тип поля, выход за границы диапазона, нехватка полей)

2. **Публичный фасад** (`validate_config(path: str) -> bool`):
   - Соответствует сигнатуре из тестового задания.
   - Перехватывает исключения `ConfigError`, логирует детальное предупреждение (`logger.warning`) и возвращает `False`.
   - Перехватывает непредвиденные системные исключения (`Exception`), предотвращая аварийное падение вызывающего сервиса.

  

---
### 3. Стандарты безопасности

1. **Защита от отказа в обслуживании (DoS по памяти)**:
   Перед чтением файла в память проверяется его размер (`st_size`). Установлен лимит `MAX_CONFIG_FILE_SIZE_BYTES = 10 МБ`. Попытка скормить валидатору гигабайтный дамп будет отклонена без риска OOM (Out Of Memory).

2. **Проверка спецзначений чисел**:
   Для поля `timeout` исключены значения `math.isnan(timeout)` и `math.isinf(timeout)`.

3. **Безопасная работа с путями**:
   Используется `pathlib.Path`, проверяется, не является ли переданный путь каталогом (`is_dir()`).

4. **Кодировка UTF-8**:
   Явное указание кодировки по RFC 8259 предотвращает проблемы при запуске на разных ОС.

5. **Строгая проверка пробелов в `host`**:
   Значение `"   "` формально является непустой строкой (`len > 0`), но в реальной сети приведет к сбою DNS-клиента. В валидаторе реализована проверка `host.strip()`.

##  Альтернативные варианты реализации

  

### Вариант А: Использование Pydantic v2

```python

from pydantic import BaseModel, Field, StrictBool, StrictInt, StrictFloat

from typing import Union

  

class AppConfig(BaseModel):

    host: str = Field(min_length=1)

    port: StrictInt = Field(ge=1, le=65535)

    timeout: Union[StrictInt, StrictFloat] = Field(ge=1, le=300)

    enabled: StrictBool

```

**Плюсы**: Компактный декларативный код, автоматическая генерация схем.  

**Минусы**: Внешняя зависимость, оверхед на инициализацию, необходимость использования префиксов `Strict*` для предотвращения нежелательной коэрсии типов.

```python
SCHEMA = {

    "required": ["host", "port", "timeout", "enabled"],

    "properties": {

        "host": {"type": "string", "minLength": 1},

        "timeout": {"type": "number", "minimum": 1, "maximum": 300},

        "enabled": {"type": "boolean"},

    },

    "additionalProperties": True,

}

```
